## 核心資料流

登入頁 → `useAuth().login` → `memberApi.loginMember` → Controller → Service → Repository → BCrypt 核對 → JWT → Provider 保存 token 與會員 → Header、會員頁一起重畫。

刷新 → Provider 讀取 localStorage → GET `/api/member/me` → AOP 檢查簽章／期限／會員狀態 → Controller 方法內讀取可信任 id → 回傳會員資料。

編輯 → PATCH `/api/member/me` → 只接收姓名、電話、地址 → 依 JWT id 更新本人 → Provider 更新會員 → Header 姓名同步。未提供或 null 不改；電話、地址 `""` 清空；姓名不可清空。

## 啟動與驗收

需 Node、JDK 21 以上及 Maven wrapper 所需快取／網路；副本已複製原本前端依賴，沒有更動套件或 lockfile。建議用 PowerShell 7。

```powershell
cd 'C:\Users\User\Documents\ChatGPT\develop\phonecase-member'
pwsh -File '.\docs\member\Start-MemberDemo.ps1'
```

此腳本先 build、型別檢查及會員測試，再啟動 loopback `http://127.0.0.1:18080/register`。它不會啟動正式 Spring Boot 應用或連資料庫。自行輸入虛構會員資料，註冊後登入；資料在服務停止時消失。停止用 Ctrl+C，不會影響原專案。若 18080 被占用，先停止上次的測試服務。

依序驗收：註冊 → 錯誤密碼 → 正確登入 → 會員中心 → 改姓名與清空電話 → 刷新 → 取消編輯 → 登出 → 直接輸入 `/profile`，應回到登入頁。

正式整合時前端仍以 `npm.cmd run dev` 啟動，沿用 `vite.config.js` 的 `/api` proxy 指向 8080；不得把測試服務當正式後端。先經團隊確認隔離 MySQL 的連線與 schema，才啟動正式後端驗收。

## 一定要能解釋的 5 個問題

1. localStorage 有 token，為什麼仍要問 `/me`？
2. Provider 跟表單各管哪些 state？
3. 401、403、網路錯誤的處理為什麼不同？
4. 後端為什麼不用前端提供的 id？
5. 電話不送、送 null、送空字串各代表什麼？

必要新觀念是 Context／Provider／useContext（跨頁共用）、useRef 版本號與 AbortController（避免舊請求覆蓋）、unknown 型別守衛（檢查外部 JSON）、PATCH 與允許欄位 DTO（限縮更新）、Transactional（一起完成資料更新）。說明及練習答案在[完整報告](會員系統技術與學習報告.md)第 8、9、13 章。
