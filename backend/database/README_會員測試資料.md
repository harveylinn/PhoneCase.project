# 會員測試資料使用說明

本資料提供第三組專題開發、前後端串接及測試使用。**僅限本機開發／受控展示環境，禁止匯入正式環境。**

## 1. 測試帳號

**登入使用 `account` 欄位，不是 Email。所有下列測試帳號的密碼皆為 `Test@123456`。**

| account | role | status | 測試情境 |
| --- | --- | --- | --- |
| `buyer01` | `CUSTOMER` | `ACTIVE` | 一般登入、購物車、結帳 |
| `buyer02` | `CUSTOMER` | `ACTIVE` | 比對不同會員的購物車與訂單，檢查資料隔離 |
| `buyer03` | `CUSTOMER` | `ACTIVE` | 會員資料及多筆訂單測試 |
| `admin01` | `ADMIN` | `ACTIVE` | 管理員權限測試 |
| `suspended01` | `CUSTOMER` | `SUSPENDED` | 停權帳號測試 |

上述資料皆為虛構測試資料。密碼存在 `password_hash` 欄位，使用 BCrypt **Cost 12**（`$2a$12$`），沒有存明文密碼。


## 2. 開發串接注意事項

- `id` 由 MySQL `AUTO_INCREMENT` 自動產生，**不要假設 `buyer01` 的 ID 一定是 1**；請用資料庫查到的實際 ID 建立購物車、訂單等關聯。
- 測試會員的 Email 為 `example.com` 假資料，不用於實際收信或寄信。
- `ADMIN` 和 `SUSPENDED` 是資料庫中的角色／狀態值；**後端仍須有對應的權限與停權檢查**，才會真正限制 API 存取。僅匯入資料不等於這些功能已經實作。
- 若登入 API 已完成，可使用上述帳號與密碼測試；若尚未完成，先以 SQL 查詢確認資料即可。
- 請勿使用真實個資、正式環境帳號或正式密碼替換這批測試資料。
